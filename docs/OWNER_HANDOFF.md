# Owner Handoff Guide

This application runs on Cloudflare Workers through OpenNext and uses Supabase for authentication, PostgreSQL, and Storage. Routine content work does not require a code deployment.

## Owner-managed content

Sign in as an administrator and use:

- **Site Settings** (`/admin/settings`) for the site name, logo/fallback initials, tagline, description, address, email, phone, WhatsApp, social links, homepage fallback copy, favicon, and SEO defaults.
- **Banners** (`/admin/banners`) to create, edit, activate, order, and delete responsive homepage hero banners.
- **Properties**, **Agents**, **Locations**, **Blog**, and **Categories** for public inventory and editorial content.
- **Inquiries**, **Viewing Requests**, and **Contacts** to process customer leads.
- **Users** to review account roles.

Site setting precedence is: an explicit database/admin value, then the corresponding deployment environment variable, then a safe code fallback. An intentional blank database value hides an optional contact/social/image value. Server Components read owner-editable values at request time, so changing them does not require a rebuild. Exact legacy bootstrap examples from migration 015 are treated as unset until an administrator changes them.

## Logos, favicons, and banners

Admin uploads go to the existing public `site-assets` bucket. Accepted application upload formats are JPEG, PNG, and WebP, with a 5 MB maximum. Object paths and UUID filenames are generated by the server:

- `branding/logo/{uuid}.{ext}`
- `branding/favicon/{uuid}.{ext}`
- `homepage/banners/{uuid}/{uuid}.{ext}`

The application validates MIME type and image structure. It updates the database before removing an old managed object, checks references before direct cleanup, and never deletes an external/manual URL. Removing the main logo restores the configured text initials.

For image banners, provide a wide desktop image and a portrait/mobile crop when useful. Video banners accept a validated desktop MP4 up to 25 MB, an optional mobile MP4 up to 15 MB, and an optional JPEG/PNG/WebP poster up to 5 MB. A mobile MP4 prevents the desktop source from being selected on small screens. Videos autoplay muted and inline; carousel videos advance when playback ends, while a single video loops. Reduced-motion visitors receive the poster/static fallback. CTA destinations may be an internal path beginning with `/` or an absolute HTTP(S) URL.

## Deployment

Review `PROJECT_RULES.md` before production work. The normal production command remains:

```bash
npm run build:cloudflare
npx wrangler deploy --keep-vars
```

Always retain `--keep-vars`; otherwise remotely configured values can be removed. Never put secrets in `wrangler.jsonc`, tracked `.env` files, browser code, or `NEXT_PUBLIC_*` variables. Required secrets include the Turnstile secret and `SUPABASE_SECRET_KEY`; Cloudflare native Rate Limiting bindings must remain attached.

## Supabase

Apply reviewed migrations in numeric order with the linked Supabase CLI. Migration 021 adds the homepage banner table. Migration 022 adds backward-compatible video fields and raises the `site-assets` per-object ceiling to 25 MB while the application retains stricter media-specific limits. Do not weaken RLS or grant anon/authenticated lead-table inserts: public form ingestion must remain:

`Worker rate limiter → validation → Turnstile → trusted server writer`

Storage writes remain admin-session/RLS controlled. The server writer secret is only for the three public lead APIs.

## Selling or transferring the project

The buyer should change owner-managed branding/content, then update or rotate Cloudflare ownership/API tokens, Supabase ownership/database and API credentials, admin accounts, Turnstile credentials/hostnames, Git hosting, and deploy credentials. Rotate one credential at a time, update the remote Worker, deploy with `--keep-vars`, test the relevant path, and only then revoke the old credential. Never print secrets into tickets, chat, Git, logs, or screenshots.

## Future custom domain checklist

No custom domain is required today. When one is added:

1. Attach it to the Cloudflare Worker.
2. Set `NEXT_PUBLIC_SITE_URL` to the canonical origin.
3. Update Supabase Auth Site URL and callback redirect URLs.
4. Add the hostname to Turnstile and `TURNSTILE_ALLOWED_HOSTNAMES`.
5. Verify canonical, Open Graph, sitemap, robots, login/signup callback, and email links.
6. Enable strict HSTS only after HTTPS and redirects are stable.

## Acceptance and data cleanup

Before handoff, test login/signup, all three forms, favorites, an admin edit, logo change, and single/multiple/no-banner states. Inspect production lead tables and public content for test records. Delete demo/test records only with explicit owner approval and after recording exact IDs; never infer that a row is disposable from its title alone.
